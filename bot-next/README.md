# WTF: новый разговорный бот

Новый TypeScript-проект на официальных Pi и Pi Durable **1.5.0**. Jev выбирает момент участия в разговоре, Pi ведёт диалог и вызывает инструменты, память сохраняет проверяемые знания, Stars учитываются отдельно от бюджета AI. Саморазвитие использует TypeScript-порт цикла [Google Research Harness²](https://github.com/google-research/harness2).

Это начальная реализация. Проверен реальный запрос к DeepSeek V4.1 Flash и Jev через OpenRouter; локальный фоновый запуск использует настройки `.env`. Настоящие Stars-платежи, генерации fal и качество длительных разговоров пока не проверены.

## Устройство

```text
Telegram → сохранённые события → Jev → Pi Durable → ответ / инструменты
                  │                    │
                  └─ память            ├─ Stars и общий USD-бюджет
                                       ├─ fal: фоновая генерация
                                       └─ навыки → Harness² → проверка → новая версия
```

Основное приложение, адаптеры, память и навыки написаны на TypeScript/JavaScript. `bot.sqlite` хранит входящие события, решения, исходящие операции, деньги, память и версии навыков. Каждый чат автоматически становится отдельной сущностью `chat_entities`, со своими памятью, навыками, настройками и разговором Pi в отдельном SQLite-файле. Добавление и удаление бота отмечаются через `my_chat_member`; обычные сообщения тоже регистрируют чат. Одним каталогом состояния владеет один процесс; бот и CLI используют общую блокировку владельца. Команды обслуживания запускаются при остановленном боте.

PostgreSQL нужен только как источник старых сообщений при миграции. В новом приложении нет зависимости от старых PHP, Temporal, Space или Dream.

## Запуск

Нужны только Node.js 24+ и npm. Весь новый бот, включая движок саморазвития, написан на TypeScript. Зависимости закреплены в lockfile; используйте `npm ci`.

```sh
cd bot-next
npm ci
cp .env.example .env
```

Заполните `.env`: токен Telegram, provider/model, ключ OpenRouter и начальный общий бюджет. По умолчанию используется `openrouter` / `deepseek/deepseek-v4.1-flash`, а Jev — `typesafe/jev-1.14` через тот же ключ. Для прямого TypeSafe задайте `JEV_PROVIDER=typesafe` и `TYPESAFE_API_KEY`.

ID чатов указывать не нужно: бот автоматически работает в личных сообщениях и группах, где его добавили, и разделяет их состояние. `TELEGRAM_CHAT_IDS` — необязательный фильтр для ограниченного теста; пустое значение включает автоматический режим. `TELEGRAM_OWNER_IDS` задаёт дополнительных глобальных владельцев; без него команды управления доступны администраторам соответствующей группы и участнику своей личной переписки. `TELEGRAM_SUPPORT_CONTACT` позволяет указать контакт по платежам; по умолчанию бот направляет к администраторам чата. Для чтения всех групповых сообщений должен быть выключен Privacy Mode в BotFather либо боту нужны права администратора. Параметры fal необязательны, но для генерации должны быть заполнены вместе.

```sh
npm run check
npm test
npm run build
npm start
```

Не запускайте старый и новый poller с одним Telegram token одновременно. Для отдельной проверки поведения удобнее другой бот и тестовый чат. Текущая интеграция предназначена для групповых сообщений и ответов; отдельный broadcast-канал с `channel_post` пока не подключён.

В чате доступны `/wtf` для сводки, `/feed 100` для добровольного взноса Stars, `/balance` и `/paysupport`. Администратор группы, участник своей личной переписки или глобальный владелец может использовать `/pause`, `/resume` и `/learn описание задачи`. Эти команды действуют только на текущий чат. Пауза останавливает разговорные ответы; ранее принятые внешние задачи и платежи продолжают обрабатываться.

## Выпуск через GitHub Actions

Workflow `.github/workflows/build-and-deploy.yaml` проверяет TypeScript и тесты, собирает Linux-контейнер из `bot-next/Dockerfile`, публикует его в `ghcr.io/shanginn/wtf_happend_bot` и проверяет опубликованный образ по digest. В production попадает точный проверенный образ с меткой исходного commit. Pull request запускает проверки; push в `master` или ручной запуск workflow на `master` также выполняет выпуск. Устаревший commit не переключает production, если `master` уже обновился.

Доступ к namespace `wtfhappendbot` использует существующий GitHub Secret `KUBECONFIG`, проверенный TLS и ограниченный SSH-транспорт; TypeScript-помощник удаляет приватные файлы после job. Токены Telegram и OpenRouter берутся из существующего Kubernetes Secret `wtf-happend-bot-secret` и не включаются в образ. Локальные `.env`, состояния и архивы исключены из build context.

CI приостанавливает старые release-reconciler CronJobs, останавливает предыдущий poller и ждёт удаления его Pod. Затем запускает одноразовую проверку контейнера, Jev и модели с общим денежным учётом, освобождает том проверки и поднимает один `wtf-happend-bot-next`. Проверка не отправляет сообщений в Telegram. Если она или rollout не завершаются, CI восстанавливает предыдущий poller и состояния контроллеров. Последующие обновления возвращают предыдущий TypeScript-образ при ошибке; PHP самопроизвольно не запускается.

Состояние лежит на постоянном томе `wtf-happend-bot-next-data` (`unified-apps-ha`); стратегия `Recreate` и блокировка Pi исключают совместную запись двух экземпляров. Образы Kubernetes получает из GHCR, прямой доставки архивов на узлы нет. Проверки здоровья требуют свежего успешного Telegram polling. Исходные данные старого бота сохраняются отдельно; миграция знаний запускается явной командой.

## Бюджет и поддержка Stars

`BOT_BUDGET_USD` задаёт исходный **общий** лимит только при создании пустого финансового хранилища. После этого изменение переменной не добавляет деньги и не сбрасывает расходы. При остановленном боте пополнение лимита выполняется явно:

```sh
npm run cli -- budget fund --usd 10
```

Это внутреннее разрешение расходовать средства владельца; команда не пополняет счёт у OpenAI, fal или другого провайдера. Их баланс нужно обеспечить отдельно. Перед платным действием резервируется верхняя оценка стоимости; неизвестный исход сохраняет резерв или консервативный расход до сверки, чтобы повтор после сбоя не породил незаметную оплату.

Stars — добровольная поддержка. Бот умеет создавать счёт, проверять pre-checkout, учитывать `successful_payment` и возвраты по уникальному идентификатору платежа. Он может предложить поддержку через инструмент `request_support`, с ограничением частоты. Полученные Stars **не превращаются автоматически в USD-лимит**: у Telegram и AI-провайдеров разные балансы. Перевод доната не даёт дополнительных полномочий в чате.

## Память

Факт содержит субъект, текст, устойчивый ID источника, подтверждающую цитату и дату. Поиск ограничен нужным чатом, но фильтрует всю его сохранённую память до применения `limit`, поэтому старые релевантные факты не теряются за последними записями.

Текущий поиск лексический: нормализация текста и совпадение слов. Эмбеддингов и семантического ранжирования пока нет. Когда Jev выбирает молчание, принятое событие остаётся в истории, но отдельное фоновое извлечение фактов из каждого такого события ещё не реализовано. `forget` удаляет активное содержание и создаёт хешированные запреты по тексту/источникам; повторный импорт не должен восстановить забытое. После забывания через инструмент Pi следующий разговор начинает новый агентный контекст. Это не физическое удаление прежних Pi transcripts: их очистка вместе с архивами миграции и резервными копиями требует отдельной политики хранения.

## Миграция существующих сообщений

Переносится новое знание, а не таблицы, workflow history или старая структура скиллов. Для PostgreSQL задайте `LEGACY_DATABASE_URL`; желательно использовать отдельного пользователя только с `SELECT`. Экспорт дополнительно выполняет `REPEATABLE READ READ ONLY` и завершается `ROLLBACK`.

```sh
npm run migrate -- inventory --source legacy --chat CHAT_ID
mkdir -m 700 -p var/migration
npm run migrate -- export --source legacy --chat CHAT_ID --out var/migration/legacy.jsonl
```

`CHAT_ID` заменяется на числовой ID нужной группы. Экспорт берёт `update_records` и раннюю `messages`, объединяет одинаковые сообщения, предпочитает последнюю правку и сохраняет идентичность автора. Из Telegram payload не копируются контакты, местоположение, file IDs, вложения и вложенные цитируемые сообщения. Выходной JSONL содержит текст выбранных сообщений и поэтому остаётся частным промежуточным архивом: файл создаётся с правами `0600`, существующий путь не перезаписывается.

Forgotten memory сопоставляется с источниками по цепочкам ревизий, provenance и точным цитатам в том же чате, включая прежние Space по темам. По умолчанию выбран старый `BOT_INSTANCE_ID=default`; для другого экземпляра добавьте `--legacy-bot-instance ИМЯ` к `inventory`/`export`. Если в чате найдены привязки только другого экземпляра или старое забывание нельзя сопоставить надёжно, экспорт останавливается с объяснением. Исторические удаления, которых в старой БД нет, восстановить невозможно.

```sh
npm run migrate -- knowledge --source var/migration/legacy.jsonl --chat CHAT_ID --until 2026-11-06T23:59:59+05:00 --max-cost-usd 2 --chunk-size 10 --dry-run
npm run migrate -- status --run RUN_ID
npm run migrate -- resume --run RUN_ID
npm run migrate -- review --run RUN_ID
npm run migrate -- apply --run RUN_ID
```

`RUN_ID` берётся из отчёта подготовки. `knowledge --dry-run` извлекает кандидатов и **может расходовать указанный бюджет на модель**; dry-run означает отсутствие записи в активную память. `prepare` с теми же обязательными параметрами создаёт только manifest и chunks без вызова модели. `review` показывает сами кандидаты с ID источников и точными цитатами: по умолчанию 100, продолжение через `--offset` из поля `nextOffset`, размер страницы через `--limit` (до 1000). Вывод остаётся частным. После просмотра `apply` выполняет атомарное применение готовых знаний; повторный `apply` не создаёт дубликаты.

По умолчанию chunk содержит до 40 сообщений и получает не более $0.25; в примере выбран более компактный размер 10. Параметры `--chunk-size` (1–100) и `--max-chunk-cost-usd` позволяют изменить эти границы; общий `--max-cost-usd` остаётся пределом всего запуска. Pi probe ограничивает объём входа, поэтому длинные сообщения требуют меньшего chunk. Если верхняя оценка выбранной модели выше allowance одного chunk, увеличьте именно `--max-chunk-cost-usd` или выберите более дешёвую модель. Независимо от миграционного лимита действует общий USD-бюджет приложения.

Manifest фиксирует хеш источника, chat scope, cutoff, версии экстрактора/политики и бюджет. Завершённые chunks не оплачиваются заново при `resume`; подмена provider/model при продолжении отклоняется. Для `prepare` тоже задайте выбранные `PI_PROVIDER` и `PI_MODEL`, чтобы версия была закреплена до вызова модели. Изменённый исходный файл требует нового manifest. Для продолжения после потери ответа платного экстрактора нужна сверка: `status` показывает `unresolvedChunks`, программный API `reconcileChunk` принимает подтверждённый результат/стоимость. Автоматического повторного вызова в таком состоянии нет; отдельная операторская CLI-команда сверки пока не реализована.

Формат самостоятельного JSONL-экспорта:

```json
{"id":"-100123:42","scope":"-100123","authorId":"telegram_user:7","text":"Я занимаюсь садом.","occurredAt":"2026-11-01T10:00:00Z","revision":0}
{"kind":"forget","scope":"-100123","sourceIds":["-100123:41"]}
```

Миграционный ввод ограничен 100 000 записями и 128 MiB. Экспорт PostgreSQL также ограничивает число исходных строк и размер рабочего набора. Поддержаны таблицы `public` из миграций проекта; неизвестная схема отклоняется. Экспорт не восстанавливает сообщения, не сохранённые старым ботом, не читает ответы из `tool_execution_records`/`llm_provider_responses` и не расшифровывает медиа. Старые таблицы не меняются. При переходе на новый бот нужен финальный экспорт до согласованного cutoff; переключение ingress и живая миграция здесь не выполнялись.

## Harness² на TypeScript и динамические навыки

В `src/harness2/` находится адаптированный TypeScript-порт используемого алгоритма из commit `6868817518876de8fd170c6a8354daca273b6191` репозитория Google Research. Исходная ревизия, контрольные суммы оригиналов и отличия описаны в `harness2/`; лицензия Apache-2.0 сохранена. Это локальный порт, а не официальный TypeScript-релиз Google.

Движок выполняет построение кандидатов, испытание, композицию, анонимный выбор и рефлексию непосредственно в Node.js. Сохранены параллельный и последовательный режимы с 4k пробами и 3k этапами улучшения. Модельные вызовы обслуживает Pi; лимиты расходов и реальные инструменты остаются у приложения. Исследовательские CLI и внешние исполнители не требуются.

Редактируемый артефакт — `AGENTS.md`, `.agents/skills/<name>/SKILL.md` и небольшие `scripts/*.ts`/`*.js`. Скрипт является телом функции с JSON-переменной `input` и `return`, исполняется в QuickJS через официальный Pi Code Mode. В текущем варианте у него нет сети, файловой системы хоста, npm imports и прямого доступа к секретам; внешние действия выполняются инструментами приложения. Версии содержимого неизменяемы и адресуются хешем.

Бот может самостоятельно поставить задачу `improve_skills`. Автоматический цикл включён: после каждых 50 обработанных пользовательских событий, дошедших до Jev, создаётся задача улучшения, не чаще одного раза в 24 часа на чат. События с решением «молчать» тоже учитываются; служебные команды и события во время паузы — нет. `/learn` оставлен владельцу как дополнительный запуск. Кандидат проходит проверки скриптов и сравнение поведения, затем автоматически активируется при успешной оценке. Для одного чата не накапливаются параллельные незавершённые задачи улучшения.

```sh
npm run evolve -- --chat CHAT_ID --goal "Научиться делать короткую сводку договорённостей"
```

Расходы ограничиваются общим бюджетом и `EVOLUTION_MAX_USD`; улучшение не должно расходовать весь остаток, нужный разговору. Пока контроль качества использует небольшой фиксированный набор и модельную оценку. Убедительного результата «бот стал лучше на реальных разговорах» ещё нет; автоматическая активация версии не заменяет последующее наблюдение.

## fal.ai

Сейчас реализована **генерация изображения из текста** через один настроенный `FAL_ENDPOINT`, с заранее проверенным потолком `FAL_MAX_COST_USD`. Задание сохраняет идентификатор провайдера, опрашивает очередь и доставляет изображение отдельно. Неизвестный результат отправки заказа блокирует автоматический повтор платного submit.

Редактирование изображений, видео, выбор нескольких моделей и подписанные webhooks пока не подключены. Понимание фотографии разговорной моделью — отдельная функция Pi и не означает наличие image-to-image в fal. Telegram URL с bot token не передаётся внешнему AI-провайдеру.

## Проверки и эксплуатационные границы

`npm test` использует локальные SQLite-базы и подставные провайдеры. TypeScript-движок проверяется в обоих режимах, включая сравнение с сохранёнными эталонами исходного алгоритма. Все тесты выполняются в Node.js, не покупают генерации и не отправляют сообщения людям. Для PostgreSQL проверены соответствие исходным миграциям и нормализация записей; соединение с реальной старой БД и SQL-экспорт пока не испытывались.

Host SQLite использует `synchronous=FULL`. Официальный Pi SQLite backend по умолчанию использует WAL/`NORMAL`: восстановление после падения процесса не равно гарантии сохранения последнего commit при отказе хоста. Перед эксплуатацией нужны согласованный backup, проверка восстановления обеих частей состояния и сверка неизвестных внешних операций. Внутренняя идемпотентность не превращает Telegram или fal API в exactly-once.

Пока не проверены: автоматическое восстановление при потере узла, семантическая память, полноценная операторская сверка неизвестных платежных/медиа исходов, большой независимый набор оценки разговоров и автоматический мониторинг качества после активации навыка.
